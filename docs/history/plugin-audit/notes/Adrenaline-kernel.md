## 2. Module start / stop
module_start (kernel/main.c:161-209), in order:
1. `taiGetModuleInfoForKernel(KERNEL_PID, "SceCompat", &info)`; on failure `return res` (the raw negative error, not `SCE_KERNEL_START_FAILED`/`NO_RESIDENT`; kernel/main.c:167-169). Nothing has been installed yet, so nothing to undo. `module_nid = info.module_nid` (kernel/main.c:171).
2. Hook 0 — `switch (info.module_nid)` (kernel/main.c:174): 3.60 retail (0x8F2D0378) → `taiHookFunctionOffsetForKernel(KERNEL_PID, &sceCompatSecSetSSRAMAclRef, info.modid, 0, 0x2AA4, 1, …)` (kernel/main.c:175-176); 3.65/3.67/3.68/3.69/3.70 retail (0x07937779/0x71BF9CC5/0x7C185186/0x52DFE3A7/0xE0E3AA51) → offset 0x2AE8 (kernel/main.c:179-184). No `default:` — on an unknown SceCompat NID `n_hooks` stays 0 and hook 0 is skipped (see module_stop consequence below). Result stored in `hooks[n_hooks++]`, not checked.
3. Hooks 1-3 — three `taiHookFunctionImportForKernel(KERNEL_PID, …, "SceCompat", 0x6F25E18A /*SceSysmemForDriver*/, NID, …)`: 0xC94850C9 `ksceKernelAllocMemBlock`, 0x009E1C61 `ksceKernelFreeMemBlock`, 0xFFCD9B60 `ksceKernelUnmapMemBlock` (kernel/main.c:189-191). Unchecked.
4. Hook 4 — `taiHookFunctionImportForKernel(…, "SceCompat", 0x81C54BED /*SceGrabForDriver*/, 0xE9C25A28, …)` (kernel/main.c:194). Unchecked.
5. Hook 5 — `taiHookFunctionImportForKernel(…, "SceCompat", 0xFD00C69A /*SceSblAIMgrForDriver*/, 0xF4B98F66 ksceSblAimgrIsDEX, …)` (kernel/main.c:197). Unchecked.
6. Hook 6 — `taiHookFunctionExportForKernel(KERNEL_PID, &ksceKernelStartPreloadedModulesRef, "SceKernelModulemgr", 0xC445FA63, 0x432DCC7A, …)` (3.60 lib/func NID, kernel/main.c:200); if `< 0`, retry with `0x92C9FFC2, 0x998C7AE9` (3.65+ NIDs, kernel/main.c:201-202). This is the only hook whose result is examined, and only to pick the fallback; the fallback result is not checked. `n_hooks++` (kernel/main.c:203).
7. `ksceKernelLoadStartModuleForPid(ksceKernelSysrootGetShellPid(), "ux0:app/PSPEMUCFW/sce_module/adrenaline_vsh.suprx", 0, NULL, 0, NULL, NULL)` (kernel/main.c:205-206) — loads a user module into SceShell at kernel-plugin start (for the case where the skprx is loaded after boot, readme.md:25-31). Result unchecked. If SceShell is not yet running (true `*KERNEL` boot), `shell_pid` is whatever `ksceKernelSysrootGetShellPid()` returns then (not checked), and the SceShell copy is instead loaded from hook 6 (kernel/main.c:129-130).
8. `return SCE_KERNEL_START_SUCCESS` (kernel/main.c:208) unconditionally after step 1.
   Unwinding: none. If hook k fails, hooks 1..k-1 stay installed, a negative uid is stored and the module remains resident.

module_stop (kernel/main.c:211-221): seven `taiHookReleaseForKernel(hooks[--n_hooks], <ref>)` in fixed reverse order: StartPreloadedModules, IsDEX, SceGrab, UnmapMemBlock, FreeMemBlock, AllocMemBlock, SecSetSSRAMAcl (kernel/main.c:212-218); `return SCE_KERNEL_STOP_SUCCESS` (kernel/main.c:220). No guard on `uid >= 0`. No threads, memblocks or sync objects to release. The two modules loaded into SceShell / PSPEMUCFW are NOT unloaded. BUG: on an unknown SceCompat NID hook 0 was never installed so `n_hooks == 6`; module_stop still executes seven releases, pairing every uid with the wrong ref (hooks[5] released with `ksceKernelStartPreloadedModulesRef`, …) and finally `hooks[-1]` (out-of-bounds read of the static array) with `sceCompatSecSetSSRAMAclRef`. `hooks[8]` is zero-initialised (`static int hooks[8];` kernel/main.c:46), so a failed install (negative value) is passed to release unguarded.

## 6. Firmware assumptions
- No `ksceKernelGetSystemSwVersion`. Firmware is inferred from SceCompat's `module_nid` (kernel/main.c:167-171) and stored in the global `module_nid` for use inside hook 0 (kernel/main.c:50, 102-109).
- Supported SceCompat NIDs: 0x8F2D0378 3.60 retail → hook offset 0x2AA4 and IPL patch address 0x70602D58; 0x07937779 3.65, 0x71BF9CC5 3.67, 0x7C185186 3.68, 0x52DFE3A7 3.69, 0xE0E3AA51 3.70 → offset 0x2AE8 and patch address 0x70602D70 (kernel/main.c:175-184, 102-111). 3.71-3.74: NOT present → on those firmwares hook 0 is skipped, the IPL is never patched (Adrenaline CFW would not boot) and module_stop misbehaves (§2). No PDEL/PTEL/DEX NIDs.
- SceKernelModulemgr export NIDs tried in order 3.60 (0xC445FA63::0x432DCC7A) then 3.65+ (0x92C9FFC2::0x998C7AE9) (kernel/main.c:200-202).
- Import NIDs assumed stable across all supported firmwares: SceSysmemForDriver 0x6F25E18A (0xC94850C9, 0x009E1C61, 0xFFCD9B60), SceGrabForDriver 0x81C54BED::0xE9C25A28, SceSblAIMgrForDriver 0xFD00C69A::0xF4B98F66 (kernel/main.c:189-197).
- Hard-coded physical/virtual addresses not version-gated: SceCompat memblock bases 0x23000000 / 0x24000000 (kernel/main.c:58-60), PSP-emu user VAs 0x70FC0000 / 0x70602D58 / 0x70602D70 (kernel/main.c:97-110), display paddr 0x21000001 → 0x22000001 (kernel/main.c:87-88), MIPS `jal 0x88FC0000` (kernel/main.c:101); adrenaline_compat.h constants `SCE_PSPEMU_EXTRA_MEMORY 0x8B000000`, `SCE_PSPEMU_FRAMEBUFFER 0x74000000`, `ADRENALINE_ADDRESS 0xABCDE000`, `NATIVE_FRAMEBUFFER 0x0A400000` (adrenaline_compat.h:34, 38, 183, 186) — only `ADRENALINE_TITLEID` (adrenaline_compat.h:31) is actually used by kernel/main.c.
- 3.60 vs 3.65 vs 3.68+: 3.60 has its own offset/address pair; 3.65-3.70 share one pair; nothing newer is handled.

## 10. Patterns worth copying / anti-patterns
- (+) Early, honest failure when the hooked module is absent: `taiGetModuleInfoForKernel` failure returns before anything is installed (kernel/main.c:167-169) — though it should return `SCE_KERNEL_START_FAILED`/`NO_RESIDENT` rather than the raw error.
- (+) Two-NID fallback for a kernel export whose library NID changed between 3.60 and 3.65 (kernel/main.c:200-202), and firmware dispatch by the target module's own `module_nid` rather than a system-version string (kernel/main.c:167-184).
- (+) Minimal syscall surface: one export, bracketed by `ENTER_SYSCALL`/`EXIT_SYSCALL`, result copied out with `ksceKernelMemcpyKernelToUser` (kernel/main.c:138-158).
- (+) Loading the per-process user companions from a `ksceKernelStartPreloadedModules` hook keyed on title id, so they attach exactly when SceShell / the emulator process start (kernel/main.c:123-136).
- (−) Counter-based release with a fixed seven-step module_stop: when the SceCompat NID is unknown only six hooks exist, so every release gets the wrong ref and the last reads `hooks[-1]` (kernel/main.c:174-184, 211-218). Pair each uid with its ref in a table, initialise to −1 and guard `>= 0`.
- (−) No install result is checked and `hooks[]` is zero-initialised (kernel/main.c:46, 176-203); a failed hook leaves a negative uid that module_stop passes to `taiHookReleaseForKernel` unguarded.
- (−) `ksceKernelUnmapMemBlockPatched` swallows the call without TAI_CONTINUE (kernel/main.c:82-84) and `ksceKernelFreeMemBlockPatched` suppresses frees of a block chosen by base address (kernel/main.c:58-60, 68-69): both silently change SceCompat's memory lifecycle for every caller, with no restore when the plugin is stopped.
- (−) Syscall trusts `count` and uses a single-element kernel stack buffer (`SceCtrlData pad`, kernel/main.c:142, 149) — `count > 1` overruns the kernel stack; `port`/`count` are not validated.
- (−) Writes an executable opcode into PSP-emulator user memory from a kernel hook using fixed VAs (0x70602D58/0x70602D70) with no verification of the bytes being replaced (kernel/main.c:97-111).
- (−) Modules loaded into SceShell / PSPEMUCFW are never unloaded on module_stop (kernel/main.c:211-221), and `ksceKernelLoadStartModuleForPid` at module_start uses `ksceKernelSysrootGetShellPid()` without checking that SceShell exists yet (kernel/main.c:205-206).
- (−) Dead code and unused links: `debugPrintf`, `ReadFile`, `WriteFile` (kernel/utils.c:26-53, kernel/utils.h:22-31), `module_get_export_func` declaration and `taihenModuleUtils_stub` (kernel/main.c:36, kernel/CMakeLists.txt:23).

## 11. Overlay-specific
Not applicable to the kernel module — it draws nothing. Its only display-related action is rewriting the native display buffer physical address passed to SceGrab (0x21000001 → 0x22000001, kernel/main.c:86-91); the framebuffer itself is allocated by SceCompat / the PSP emulator, not by this module. (User/vsh drawing code is out of scope.)
