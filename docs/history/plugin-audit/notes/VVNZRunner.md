Evidence: README.md:3 "Kernel plugin for PS Vita that provides API to run Toshiba MeP code on Venezia"; artifact `VVNZRunner.skprx` (CMakeLists.txt:86); `include_directories(${VDSUITE_KERNEL_INCLUDE_DIRECTORIES})` (CMakeLists.txt:24-26); all linked stubs are `*ForDriver_stub` / `taihenForKernel_stub` (CMakeLists.txt:70-83); `taiGetModuleInfoForKernel(KERNEL_PID, ...)` (main.c:313, 324); `sceKernelRegisterProcEventHandler` (main.c:337); `sceKernelCopyFromUser/ToUser` (main.c:184, 209). The vdsuite SDK names kernel APIs `sce*` (not `ksce*`), which is why no `ksce*` appears. Consequently it allocates NOTHING inside SceShell (no PAF, no `sceKernelAllocMemBlock` anywhere in the plugin: grep of main.c/memory.c/codec_engine_bridge.c finds no AllocMemBlock/HeapAlloc/malloc) and NOTHING at module_start (§5).

## 1. Process context
- One module, `VVNZRunner` (lib.emd:1), `sceModuleInfo_type: 6` (lib.emd:2 — kernel module type), built as `VVNZRunner.skprx` via `VDSuiteSignElf("${PROJECT_NAME}.skprx" "${PROJECT_NAME}.elf" COMPRESS ON STRIP ON)` (CMakeLists.txt:86). taiHEN section: `*KERNEL` (kernel SELF; no install line in README — "not found in source").
- Exports one library `VVNZRunner` with `attr: auto_export` and `attr: syscall_export` (lib.emd:5-6), i.e. 24 syscalls callable from any user process (lib.emd:10-33). User apps link `-lVVNZRunner_stub` (samples_new/arm_sample_hello_draw/VVNZRunnerSample/VVNZRunnerSample.vcxproj:53).
- Memory: the module image and statics live in kernel. It owns no memblocks. It maps the caller's CDRAM memblock into kernel VA (`sceKernelUserMap`, main.c:105) and into Venezia (`_sceAvcodecMapMemoryToVenezia`, main.c:135), writes to fixed kernel VAs of the Venezia image/SPRAM (common.h:13-14), and pokes SceCodecEngineWrapper's data segment (`_vnzExecClockFrequency`, main.c:318, 244). Nothing in SceShell; nothing in a game except what the game itself allocates and passes in.

## 2. Module start / stop
module_start (main.c:308-364), in order:
1. `taiGetModuleInfoForKernel(KERNEL_PID, "SceCodecEngineWrapper", &info)`; on failure `return SCE_KERNEL_START_SUCCESS` (main.c:313-314) — module stays resident with every function pointer NULL and its syscalls live.
2. Five `module_get_offset` into SceCodecEngineWrapper, results unchecked: seg0 `0x8C|1` → `_sceVeneziaEventHandler`, `0x36EC|1` → `_sceVeneziaGetProcessorLoad`, seg1 `0xBC` → `_vnzExecClockFrequency` (data), `0x161FC|1` → `_sceCodecEngineAllocMemoryFromUnmapMemBlock`, `0x162FC|1` → `_sceCodecEngineFreeMemoryFromUnmapMemBlock` (main.c:316-320).
3. `taiGetModuleInfoForKernel(KERNEL_PID, "SceAvcodec")`; on failure `return SCE_KERNEL_START_SUCCESS` (main.c:324-325) — leaves step-2 pointers set but no proc-event handler and no inject.
4. `module_get_offset` SceAvcodec seg0 `0x89C0|1` → `_sceAvcodecMapMemoryToVenezia`, unchecked (main.c:327).
5. `SceProcEventHandler handler` with `.stop = .start = procEvHandler`, `.exit = .kill = procEvExitHandler`; `sceKernelRegisterProcEventHandler("SceVeneziaProcEvHandler", &handler, 0)`, result unchecked (main.c:329-337).
6. Direct kernel-VA writes into the Venezia firmware image: `*(u32*)(0x28200000 + 0xEADF0) = 0x8EAE70` and `memcpy(0x28200000 + 0xEAE70, s_injectCode, 24)` (main.c:340-341; constants common.h:14, 34-35, 28). Original bytes are NOT saved.
7. `_vnzDoReset()` → `_sceVeneziaEventHandler(0, 0x400e, …)`, `(1, 0x1000e, …)` — resets Venezia on the boot path (main.c:355, 56-61).
8. `#ifdef ENABLE_GPO_PROXY` thread creation — compiled out (`//#define ENABLE_GPO_PROXY`, main.c:18; block main.c:357-361).
9. `return SCE_KERNEL_START_SUCCESS` (main.c:363). Never returns FAILED/NO_RESIDENT. Nothing is undone on either early return.

module_stop (main.c:366-369): `return SCE_KERNEL_STOP_SUCCESS` (main.c:368) only. NOT done: unregister the proc-event handler (dangling kernel callback into unloaded code), restore the 28 patched bytes of the Venezia image, `vnzBridgeRestore()` for a still-registered process (kernel mapping `s_blockMapId` and Venezia mapping leak), restore `*_vnzExecClockFrequency` to 166. No threads/memblocks/sync objects exist to release.

## 10. Patterns worth copying / anti-patterns
- (+) Bounded user→kernel copies with an explicit size cap derived from the mailbox size (`userArgSize > COMM_HEAP_SIZE - sizeof(SceVeneziaCommParam) → E2BIG`, main.c:181-182) and every out-parameter written with `sceKernelCopyToUser` rather than direct deref (memory.c:23, 59; codec_engine_bridge.c:15, 48, 93, 103, 113, 124).
- (+) Process-exit hook that automatically tears down per-process state (`procEvExitHandler → vnzBridgeRestore`, main.c:268-279), and clock restoration on process suspend/resume (main.c:252-265).
- (+) Validating the ELF magic before trusting header fields (main.c:113-116) and requiring 256 KiB-aligned block sizes (main.c:99).
- (+) Explicit allowlist of legal Venezia clock values (main.c:242).
- (−) module_start swallows every failure and returns SUCCESS with NULL function pointers while 24 syscalls stay reachable (main.c:313-327, 363); `vnzBridgeGetVeneziaExecClockFrequency` then dereferences NULL in kernel (main.c:235-238).
- (−) module_stop releases nothing: proc-event handler stays registered pointing at unloaded code, 28 patched bytes in the Venezia image are never restored (originals never saved), a registered process's mappings leak (main.c:340-341, 366-369).
- (−) Kernel memory read/write primitive exposed to user space: `vnzBridgeMemcpyToSpram/FromSpram/GetSpramValue` bound `spramOffset + size` against `SPRAM_MEMSIZE = 0x2500000` (37 MiB) while the SPRAM mapping is `SPRAM_MAP_SIZE = 0x20000` (128 KiB) and the Venezia image starts 1 MiB later at 0x28200000 (memory.c:46-68; common.h:13-14, 20, 24) — any process can overwrite the Venezia firmware image and ~36 MiB of kernel VA beyond it.
- (−) No ownership check on the syscalls: `vnzBridgeExec*`, `vnzBridgeRestore`, `vnzBridgeSetVeneziaExecClockFrequency`, SPRAM copies only test `s_registeredPid != INVALID`, never `== sceKernelGetProcessId()` (main.c:67-68, 177-178, 240-250); no mutex guards the shared globals (main.c:43-54).
- (−) Error path leaks: `return_with_unmap:` does not unmap (main.c:167-169) although `s_blockMapId` was set (main.c:105) — unlike main_old.c:159-161 which did unmap; next `vnzBridgeInject` silently overwrites the stale uid.
- (−) Operator-precedence bug makes the section search accept any PROGBITS section: `shdr->sh_flags == SHF_ALLOC | SHF_EXECINSTR && shdr->sh_type == SHT_PROGBITS` parses as `(flags == SHF_ALLOC) | (SHF_EXECINSTR && type == PROGBITS)` (main.c:118-124, condition at 120); the found `shdr` is then unused, and `e_shoff/e_shnum/e_shentsize` are trusted without bounds checks against the block size (main.c:118-119).
- (−) Hard-coded module offsets and raw writes to fixed kernel VAs without any firmware gate (main.c:316-327, 340-341; common.h:12-35); Venezia hard-reset at boot (main.c:355) and from within process-exit events (main.c:72-75, 277).
- (−) Design constraint leaks into API: the caller's ELF block must be at CDRAM paddr 0x20000000 ("Fix required paddr to VRAM base until there's better solution", main.c:140-145), so injection fails if anything else occupies the CDRAM base.
