NOT an overlay: this plugin draws nothing and never runs inside a game. It is an FTP + TCP command server that lives in SceShell. Section 11 therefore reports "not applicable" with the SceShell-side memory story instead.

## 1. Process context
- One module, `vitacompanion.suprx`, a USER plugin for the `*main` (SceShell) section: README.md:78-79 install lines are `*main` / `ur0:tai/vitacompanion.suprx`; `vita_create_self(vitacompanion.suprx vitacompanion UNSAFE CONFIG .../vitacompanion.yml)` (CMakeLists.txt:91-94); `attributes: 0` (vitacompanion.yml:2) i.e. not a kernel module; every API is `sce*`, no `ksce*` anywhere (grep over src/ and libftpvita/ finds none); the link line is all user stubs (`SceLibKernel_stub_weak`, `SceNet_stub_weak`, ... CMakeLists.txt:66-81) plus `taihen_stub` (CMakeLists.txt:61).
- All of its memory lives in the SceShell process: its module image, the 1 MiB taipool heap (main.c:24), four kinds of threads and their stacks, all sockets (`sceNetSocket("vitacompanion_cmd_sock"...)` cmd.c:128, `"FTPVita_server_sock"` ftpvita.c:1287), and the on-demand PAF/PromoterUtil sysmodules it loads into SceShell (package_installer.c:650-663, 671). It calls SceShell-internal code directly once: `shellShot()` resolved from a SceShell text offset (cmd_definitions.c:334, 359). ## 2. Module start / stop
module_start (main.c:21-40), in order:
1. `taipool_init(1 * 1024 * 1024)` (main.c:24); on `< 0` returns `SCE_KERNEL_START_FAILED` with nothing to undo (main.c:25). taipool is an external library (`taipool` CMakeLists.txt:61, header `<taipool.h>` main.c:12); its allocation type/implementation is not in this repository.
2. `#if ENABLE_LOGGING == 1` truncates `ux0:dump/vitacompanion_log.txt` (main.c:27-30) - compiled out, `ENABLE_LOGGING 0` (main.h:3).
3. `run = 1` (main.c:31), then `net_start()` (main.c:32) which only creates+starts the net thread (net.c:28-37). On failure: `run = 0; taipool_term();` and `SCE_KERNEL_START_FAILED` (main.c:34-36). `net_start` itself deletes the thread if `sceKernelStartThread` fails (net.c:33-37).
4. Returns `SCE_KERNEL_START_SUCCESS` (main.c:39). Nothing network-related happens on the boot path: the net thread first sleeps 3 s (net.c:120).
   `SCE_KERNEL_START_NO_RESIDENT` is never used.

module_stop (main.c:42-50): `run = 0` (main.c:44); `net_end()` = `sceKernelWaitThreadEnd` + `sceKernelDeleteThread` of the net thread (net.c:43-48); then `taipool_term()` (main.c:47); returns `SCE_KERNEL_STOP_SUCCESS` (main.c:49). The net thread's exit path does the real teardown: `stop_services()` (net.c:156) -> `cmd_end()` (closes listener and client socket, waits+deletes cmd thread, cmd.c:255-264) -> `ftpvita_fini()` (ftpvita.c:1556-1600: close server socket, wait+delete server thread, abort+wait+delete every client thread, delete mutex, `sceNetCtlTerm`/`sceNetTerm` only if this module initialised them, free `net_memory`); then unregisters the netctl callback (net.c:157-161) and `sceNetCtlTerm()` if it initialised it (net.c:164-167). Ordering: threads are stopped before the pool is torn down, and sockets are closed/aborted before the threads are waited on. Worst-case stop latency: the net loop sleeps 1 s between polls (net.c:153), so module_stop can block up to ~1 s plus FTP socket drains (5 s socket timeouts, ftpvita.c:42, 159-180); a client thread blocked in `sceNetRecv` is woken by `sceNetSocketAbort` (ftpvita.c:1175-1185) and exits on `SCE_NET_ERROR_EINTR` (ftpvita.c:1247-1250). Open question: `client_thread` calls `sceKernelExitDeleteThread` only when it removed itself from the list (ftpvita.c:1269-1270); when detached by `ftpvita_fini` it calls `sceKernelExitThread` so the owner can delete it (ftpvita.c:1271-1275). No hooks exist, so nothing to release. Every `free()` matches a `malloc()` on the paths read; the mutex is deleted (ftpvita.c:1581-1584). Netctl callback is unregistered (net.c:157-161).

Sums (SceShell process):

## 6. Firmware assumptions
- No `sceKernelGetSystemSwVersion` or any firmware check (grep for `SwVersion`/`3.6` finds nothing).
- The only version-dependent table is the SceShell `module_nid -> shellShot offset` switch (cmd_definitions.c:321-329): 0x0552F692 -> 0x14a928; 0x6CB01295 / 0xEAB89D5C -> 0x142d5c; 0x5549BF1F -> 0x14a980; nine NIDs (0x34B4D82E, 0x12DAC0F3, 0x0703C828, 0x2053B5A5, 0xF476E785, 0x939FFBE9, 0x734D476A, 0xE6A02F2B, 0x587F9CED) -> 0x142db4; `default: return` leaves the feature disabled (cmd_definitions.c:329). ## 8. Logging
- Compile-time disabled: `#define ENABLE_LOGGING 0` (main.h:3). When enabled: `LOG()` appends to `ux0:dump/vitacompanion.txt` via a lazily opened static fd (log.c:7-10), 256-byte stack buffer, `vsnprintf` + `sceIoWrite` (log.c:12-17), no size cap, no rotation, fd never closed; module_start truncates a differently named file `ux0:dump/vitacompanion_log.txt` (main.c:28). ## 10. Patterns worth copying / anti-patterns
- Copy: module_start does no network or file I/O; it only creates a thread that sleeps 3 s first (main.c:21-40, net.c:120), so a broken Wi-Fi stack cannot wedge SceShell boot.
- Copy: single owner of the Wi-Fi lifecycle (the net thread) does both bring-up and teardown (net.c:93-96 comment, 146-156); `cmd_end` closes sockets before joining the thread (cmd.c:257-263) and `ftpvita_fini` aborts sockets under the lock, then waits outside it (ftpvita.c:1163-1198) - correct join ordering, no wait-under-mutex.
- Copy: thread start handshake with status word + bounded spin, and the join-on-failure path deletes the thread (cmd.c:239-250; ftpvita.c:1515-1532).
- Copy: `ftpvita_init` has a complete goto-ladder unwind that only terminates Net/NetCtl if this module initialised them (ftpvita.c:1530-1553) - important in SceShell where net is shared.
- Copy: every malloc failure is handled with a client-visible error and no leak (ftpvita.c:713-719, 1354-1359; pkg:231-237).
- Copy: bounded parsers replacing scanf because "Keep FTP control parsing independent of libc scanf" (ftpvita_parse.h:6) and a resolved-offset call guarded by `memsz` (cmd_definitions.c:301).
- Anti-pattern: unbounded recursion on the cmd thread stack in `remove_tree` (pkg:58-93) driven by attacker-controlled VPK directory depth.
- Anti-pattern: `sceKernelDelayThread` busy loops instead of event flags for both startup handshakes (cmd.c:239-241, ftpvita.c:1515-1518) and an 8 s synchronous foreground poll inside a network command handler (cmd_definitions.c:195-202).
- Anti-pattern: priority 0x40 for the net and cmd threads (net.c:28, cmd.c:227) is higher than most SceShell UI threads; the 1 s poll runs forever.
- Anti-pattern: `sprintf` into fixed buffers in PASV/PORT/SIZE (ftpvita.c:256, 311, 347, 357, 1003) - sizes are provably sufficient here but not checked.
- Anti-pattern: unauthenticated FTP (`USER`/`PASS` accept anything, ftpvita.c:219-227) and an unauthenticated TCP command port that can kill apps, install VPKs and cold-reset the console (cmd_definitions.c:38-52) - acceptable for a dev tool on a LAN, not otherwise; `sceNetBind` to `INADDR_ANY` (cmd.c:135, ftpvita.c:1301).
- Anti-pattern: `log.c` cannot compile with logging enabled (missing includes, log.c:1-2).

## 11. Overlay-specific
Not applicable: the plugin draws nothing, hooks nothing, and never executes in a game process. The only in-game-adjacent behaviour is indirect: `destroy`/`kill` call SceAppMgr to terminate apps (cmd_definitions.c:101, 111), `launch` uses `psgm:play?titleid=` (cmd_definitions.c:182-186), and `screenshot` asks SceShell's own `shellShot()` to capture the current frame (cmd_definitions.c:359) - the framebuffer read and JPEG encode happen inside SceShell code, with SceShell memory, not in this module. Memory pressure story: everything is charged to SceShell (1 MiB taipool + thread stacks + on-demand 1.5 MiB PAF heap during `install`); if SceShell cannot provide it, the failing request is refused with an error reply and no state is left behind (see section 5), the plugin never degrades a game's memory budget because it allocates nothing in game processes.
