Four independent sub-plugins, each a separate CMake project producing one user-mode `.suprx`: CustomWarning, DownloadEnabler, NoLockScreen, NoTrophyMsg. Each is treated below as its own module; where a section says "all four" it applies to every module.

## 1. Process context
- All four are `*main` (SceShell) user plugins. Evidence: README install blocks put every one under `*main` (README.md:14-17 nolockscreen, 25-28 download_enabler, 36-39 notrophymsg, 51-54 custom_warning); every exports.yml has `attributes: 0` (CustomWarning/exports.yml:2, DownloadEnabler/exports.yml:2, NoLockScreen/exports.yml:2, NoTrophyMsg/exports.yml:2); every CMake target is `vita_create_self(<name>.suprx ... CONFIG exports.yml UNSAFE)` (CustomWarning/CMakeLists.txt:29, DownloadEnabler/CMakeLists.txt:27, NoLockScreen/CMakeLists.txt:25, NoTrophyMsg/CMakeLists.txt:25); only user `sce*`/`tai*` APIs are used (no `ksce*`), e.g. `taiGetModuleInfo("SceShell", &info)` (DownloadEnabler/main.c:107, NoLockScreen/main.c:28, NoTrophyMsg/main.c:37) and `taiHookFunctionImport(..., "SceShell", ...)` (CustomWarning/main.c:150).
- Process memory: all four modules are loaded into SceShell's address space and only ever touch SceShell memory (SceShell code offsets, SceShell imports, SceShell's PAF heap). Nothing runs in kernel or in a game.

## 2. Module start / stop
### CustomWarning
- module_start (CustomWarning/main.c:149-154): single step — `hooks[0] = taiHookFunctionImport(&sceSysmoduleLoadModuleInternalWithArgRef, "SceShell", 0x03FCF19D, 0xC3C26339, ...)` (main.c:150-151); result not checked; returns `SCE_KERNEL_START_SUCCESS` unconditionally (main.c:153). Nothing is allocated at module_start.
- Lazy second stage inside hook 0 (main.c:108-146), executed when SceShell loads `SCE_SYSMODULE_INTERNAL_PAF` (main.c:111): opens the warning file (main.c:114-118), `sce_paf_private_malloc(size + 2)` (main.c:123), reads it (main.c:129), BOM check with free on failure (main.c:134-137), `custom_warning++` to skip the BOM (main.c:139), then installs `hooks[1] = taiHookFunctionImport(&scePafToplevelGetTextRef, "SceShell", 0x4D9A9DD0, 0x19CEFDA7, ...)` (main.c:141-142); result not checked.
- module_stop (main.c:156-163): releases `hooks[1]` if `>= 0` (main.c:157-158), then `hooks[0]` if `>= 0` (main.c:159-160); returns `SCE_KERNEL_STOP_SUCCESS` (main.c:162). The PAF buffer is never freed, and because `custom_warning` was incremented past the BOM (main.c:139) the original pointer is lost — it could not be freed correctly. `hooks` is a zero-initialised static (`static SceUID hooks[2];` main.c:35), so if module_stop runs before PAF was ever loaded, `hooks[1] == 0` passes the `>= 0` guard and `taiHookRelease(0, ...)` is called with a bogus uid.
### DownloadEnabler
- module_start (DownloadEnabler/main.c:104-174): `taiGetModuleInfo("SceShell", &info)` (main.c:107); `switch (info.module_nid)` (main.c:108) selects one of 7 offset sets; each case does `hooks[0] = taiInjectData(info.modid, 0, <off>, "GET", 4)`, `hooks[1] = taiHookFunctionOffset(&ExportFileRef, ...)`, `hooks[2] = taiHookFunctionOffset(&GetFileTypeRef, ...)` (e.g. main.c:111-113). No `default:`; unknown SceShell → nothing is patched. No result is checked; returns `SCE_KERNEL_START_SUCCESS` unconditionally (main.c:173). Nothing allocated at module_start.
- module_stop (main.c:176-185): `hooks[2]` (taiHookRelease), `hooks[1]` (taiHookRelease), `hooks[0]` (taiInjectRelease), each guarded `>= 0` (main.c:177-182); returns STOP_SUCCESS (main.c:184). `static SceUID hooks[3];` is zero-initialised (main.c:29), so on an unmatched firmware all three releases are called with uid 0.
### NoLockScreen
- module_start (NoLockScreen/main.c:25-72): `taiGetModuleInfo("SceShell", &info)` (main.c:28); opcode word `0xBF002001` = `movs r0,#1; nop` (main.c:29); switch on module_nid (main.c:31) installs up to two `taiInjectData(info.modid, 0, <off>, &opcode, 4)` (e.g. main.c:33-34); the PDEL cases explicitly set `hooks[0] = -1` and inject only one site (main.c:38-39, 60-61). No default; results unchecked; returns START_SUCCESS unconditionally (main.c:71). No allocation.
- module_stop (main.c:74-81): `taiInjectRelease(hooks[1])` then `hooks[0]`, each guarded `>= 0` (main.c:75-78); returns STOP_SUCCESS (main.c:80). `static SceUID hooks[2];` zero-initialised (main.c:22) → uid 0 released on unmatched firmware.
### NoTrophyMsg
- module_start (NoTrophyMsg/main.c:34-73): `taiGetModuleInfo("SceShell", &info)` (main.c:37); switch (main.c:38) installs one `hookid = taiHookFunctionOffset(&savedata_aid_check_ref, info.modid, 0, <off>, 1, savedata_aid_check_patched)` (e.g. main.c:40). No default; result unchecked; returns START_SUCCESS (main.c:72). No allocation.
- module_stop (main.c:75-80): `if (hookid >= 0) taiHookRelease(hookid, ...)` (main.c:76-77); returns STOP_SUCCESS (main.c:79). `hookid` IS initialised to -1 (`static SceUID hookid = -1;` main.c:24), so this one is correct on unmatched firmware.
### Common
- No module ever returns START_FAILED or NO_RESIDENT; a failed install leaves a negative uid in the array and the module stays resident doing nothing. No threads, mutexes, or memblocks exist, so there is nothing else to undo. Ordering in every module_stop is reverse of install (last installed released first).

## 6. Firmware assumptions
- No `sceKernelGetSystemSwVersion` anywhere. Firmware is identified indirectly by SceShell's `module_nid` from `taiGetModuleInfo` (DownloadEnabler/main.c:107-108, NoLockScreen/main.c:28-31, NoTrophyMsg/main.c:37-38).
- Supported SceShell NIDs (identical set in the three offset-based modules): 0x0552F692 3.60 retail, 0x6CB01295 3.60 PDEL, 0xEAB89D5C 3.60 PTEL, 0x5549BF1F 3.65, 0x34B4D82E 3.67, 0x12DAC0F3 3.68, 0x0703C828 3.69, 0x2053B5A5 3.70, 0xF476E785 3.71, 0x939FFBE9 3.72, 0x734D476A 3.73, 0xE6A02F2B 3.65 PDEL, 0x587F9CED 3.65 PTEL (DownloadEnabler/main.c:109-168; NoLockScreen/main.c:32-67; NoTrophyMsg/main.c:39-68).
- 3.60 vs 3.65 vs 3.68+: separate offset sets per case; 3.65/3.67/3.68 share one set and 3.69-3.73 share another in DownloadEnabler (only the data inject offset differs between the two groups: 0x50A9E8 vs 0x50AA28, DownloadEnabler/main.c:137 vs 149; code offsets identical at 0x11644E/0x11B63C); 3.65-3.73 share a single set in NoLockScreen (main.c:47-56) and NoTrophyMsg (main.c:51-59).
- Unknown firmware: no `default:` branch in any switch → no patch applied, module stays resident and returns SUCCESS; nothing breaks except the uid-0 release issue on stop (§2). This is safe-by-omission: wrong offsets are never applied to an unknown SceShell.
- CustomWarning has no firmware table at all: it uses import NIDs (SceSysmodule 0x03FCF19D::0xC3C26339, ScePafToplevel 0x4D9A9DD0::0x19CEFDA7, CustomWarning/main.c:150, 141) and PAF text ids 0x76A1B071 / 0x72411882 (main.c:42), which are assumed stable across firmwares — not version-gated.

## 10. Patterns worth copying / anti-patterns
- (+) Firmware dispatch keyed on SceShell `module_nid` via `taiGetModuleInfo`, with no default branch, so an unknown SceShell is never patched with wrong offsets (DownloadEnabler/main.c:107-170; NoLockScreen/main.c:28-68; NoTrophyMsg/main.c:37-69).
- (+) `TAI_CONTINUE` first, then post-filter the return code — minimal-intrusion hooks with no state (NoTrophyMsg/main.c:27-30; DownloadEnabler/main.c:93-98).
- (+) Initialise the hook uid to -1 and guard release (`static SceUID hookid = -1;` NoTrophyMsg/main.c:24, 76).
- (+) Lazy install of an import hook only after the providing library is loaded in the target process, triggered from a hook on the module loader (CustomWarning/main.c:111, 141-142); PAF stubs linked weak so the plugin itself loads before ScePaf exists (CustomWarning/CMakeLists.txt:24).
- (+) `movs r0,#1; nop` 4-byte inject to force a boolean return, released on stop (NoLockScreen/main.c:29, 33-34, 75-78).
- (−) Zero-initialised uid arrays `static SceUID hooks[N];` (CustomWarning/main.c:35; DownloadEnabler/main.c:29; NoLockScreen/main.c:22): on an unmatched firmware, or before the lazy hook is installed, module_stop passes uid 0 to taiHookRelease/taiInjectRelease. NoLockScreen half-fixes this only in the PDEL cases (`hooks[0] = -1;` main.c:38, 60).
- (−) No hook install result is ever checked, and module_start never fails (CustomWarning/main.c:150-153; DownloadEnabler/main.c:107-173; NoLockScreen/main.c:31-71; NoTrophyMsg/main.c:38-72).
- (−) Blocking file I/O, heap allocation and a taiHEN syscall inside a hook on SceShell's start-up path (CustomWarning/main.c:108-146); the PAF buffer is never freed and its base pointer is lost by `custom_warning++` (main.c:139, 156-163); after a failed BOM check the freed pointer is left non-NULL (main.c:135-136) — benign only because CW-1 is never installed in that path. If PAF were loaded a second time, a second buffer and a second CW-1 hook would be created and the first uid overwritten (main.c:141).
- (−) Off-by-one in the random picker: the counting loop increments `num_files` on the terminating `ret == 0` iteration (CustomWarning/main.c:67-71), so `choice` ranges over N+1 values (main.c:80); `choice == 0` breaks before any `sceIoDread` (main.c:88-89) and uses the stale `entry` from the first pass (main.c:99-101). A `CHECK` failure after the second `sceIoDopen` (main.c:83-84, 91) jumps to `fallback` without closing `dfd`.
- (−) 2.5 KiB of stack arrays plus an unbounded `sceIoGetstat` loop inside a hook running on a SceShell thread whose stack size the plugin does not control (DownloadEnabler/main.c:35-38, 68-80). `file_name` read with `sceIoPread(..., sizeof(file_name), ...)` is not guaranteed NUL-terminated before `sceClibStrrchr`/`sceClibStrncpy` (main.c:51, 56-64).
- (−) Hard-coded raw offsets into SceShell per firmware with no sanity check of the bytes being patched (all three offset-based modules).
