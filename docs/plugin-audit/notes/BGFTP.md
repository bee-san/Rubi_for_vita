All APIs are user `sce*`; no `ksce*`.
- Neither module lives in SceShell, kernel or a game. taiHEN section: none — installed as a `.vpk`/`.pkg` app (README.md:11, BGFTP/BGFTP.vcxproj:75, 80), not via `ux0:tai/config.txt`.
- README claims (not verifiable from source): runs "on system-reserved core", works alongside games and in sleep mode, is terminated when the launcher's LiveArea is peeled off or an enlarged-memory game starts (README.md:4, 15-19). No CPU affinity is set anywhere in source (all `sceKernelCreateThread` calls pass affinity 0: ftpvita.c:1055, 1148); core placement is the OS's bg-app policy.

## 10. Patterns worth copying / anti-patterns
- (+) Two-process design: a minimal launcher that starts the bg-app and exits at once, so no LiveArea app stays resident (BGFTP/main.c:60-68), and `sce_process_preload_disabled` trims both processes' preloaded modules (BGFTP/main.c:11-13; BGFTP_bgapp/main.c:23-25).
- (+) Explicit, bounded libc heap (`sceLibcHeapSize = 14 MiB`, BGFTP_bgapp/main.c:28) and total-transfer-memory budgeting by dividing one buffer size over concurrent operations (`ALIGN(file_buf_size / active_op_count, 4K)`, ftpvita.c:519, 593), with a graceful "550 Could not allocate memory" on failure (:528-531, :610-613).
- (+) Reuse an already-initialised net stack and never tear down what you did not create (`sceNetShowNetstat()==0 → net_init = -1`, ftpvita.c:1100-1103; conditional `sceNetTerm` :1215-1216).
- (+) Library has a correct-looking shutdown recipe: close the listening socket to unblock `accept`, join the server thread, `sceNetSocketAbort` each client's sockets with preservation flags, join each client thread, then delete the mutex and terminate net (ftpvita.c:1191-1225, 883-919).
- (−) …but BGFTP never calls `ftpvita_fini`; its main thread spins forever at 100 Hz issuing `sceKernelPowerTick(DISABLE_AUTO_SUSPEND)` (BGFTP_bgapp/main.c:109-112), so the device cannot auto-suspend while the app lives (README.md:14 confirms), and the IP-wait loop has no timeout (ftpvita.c:1128-1131) — offline, the bg-app hangs silently before any notification.
- (−) Unchecked allocations and object creation: `malloc(client)` (:1060), `malloc(net_memory)` (:1105), both `sceKernelCreateThread` (:1053, :1147), `sceKernelCreateMutex` (:1152), `sceNetSocket/Bind/Listen` with `ret` declared `UNUSED` (:999, :1006-1024).
- (−) `active_op_count` is a plain global mutated from every client thread without `client_list_mtx` (ftpvita.c:517, 530, 552, 591, 612, 640) — racy buffer sizing. On `malloc` failure the opened `fd` is leaked (:527-532, :609-614) and `receive_file` has already truncated the target file (:597-607).
- (−) Remote-triggerable memory corruption: `sscanf(client->recv_buffer, "%s", cmd)` into `char cmd[16]` from a 512-byte network buffer (ftpvita.c:923, 942); `sprintf(ip_str[16], "%d.%d.%d.%d", …)` with unbounded ints from PORT (:222, :226-234); `strrchr(path, '/') + 1` dereferenced without a NULL check for device-root paths like `ux0:file` (:544, :627, :631).
- (−) No authentication — `USER`/`PASS` always succeed (:137-145) — on `INADDR_ANY:1337` (:1015-1016), exporting read/write/delete/rename over `os0: vs0: ur0: sa0: tm0: ud0: vd0: pd0:` and more (BGFTP_bgapp/main.c:67-84; ftpvita.c:650-740). Anyone on the LAN can modify system partitions; there is no allowlist or bind-to-interface option.
- (−) Shutdown deadlock hazard in the library: `client_list_thread_end` holds `client_list_mtx` while `sceKernelWaitThreadEnd` (:890-918), but a client thread exiting through the generic-error branch calls `client_list_delete`, which locks the same mutex (:970-973, 866-868). Only the `SCE_NET_ERROR_EINTR` branch avoids it (:965-968).
- (−) 65.6 KiB of `.bss` for 16 device names of `PATH_MAX` bytes each (ftpvita.c:42-45) and 8.8 KiB per client with two `PATH_MAX` paths (ftpvita.h:38-68) while the control buffer is 512 B (ftpvita.h:56) — oversized for a bg-app with a tight memory budget.
