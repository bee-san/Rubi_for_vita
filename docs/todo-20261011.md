An audit of the installed agent's matching binary found both power-tick calls
pass `1`, which cancels only automatic suspension; the SDK's default `0` cancels
all idle timers. The inspected call sites are also outside synchronous pairing
and command work, so blocking requests can postpone the ticks. These are two
established keep-awake weaknesses. A later reconnect reported a new uptime, so the earlier loss
must not be described conclusively as standby rather than restart. Neither
weakness alone establishes the cause of every disconnect.
[VitaSDK timer contract](https://docs.vitasdk.org/group__SceProcessmgrKernel.html)
