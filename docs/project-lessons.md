# Vita overlay project lessons

These notes distinguish source/build checks, completed transfers, native state readback and physical in-game results. Both VOCR and Meiki completed actual CLANNAD OCR jobs on the physical Vita. Two observed Meiki jobs took 7,904/8,043 ms with clean I/O and cleanup; the user confirmed the repaired region workflow works. Hardware CER and broad compatibility remain unmeasured. See [the separate Meiki observations](meiki-trial.md#physical-clannad-observations-october-11).

- **Run inference in the game process.** Keep the overlay UI under `*main`; the current OCR worker loads under `*ALL`, filters system/homebrew titles and activates only for an enabled foreground game. Shell's spare PAF memory is not the game's USER memory. Report free USER bytes, requested/page-rounded allocations, allocator peaks and cleanup separately. Unused bytes inside a game-owned memblock remain owned by that game; subtracting displayed usage from a 256/333 MiB budget does not prove an allocation will fit. Raising a game allocation mode is not part of the current release. [Architecture and memory bounds](https://github.com/bee-san/vita-jp-overlay/blob/main/docs/vita-vn-ocr.md)

- **Keep dictionary work bounded.** Plain definitions and a disk-backed VJDICT2 index avoid loading a whole dictionary or index. Local lookup returns at most one entry at the selected Unicode character, reuses saved OCR text and does not tokenize the entire sentence or rerun capture. The current local result arena is 64 KiB, with bounded page-cache/deinflection scratch; those bounds are not total Shell residency. Retire the previous result before allocating/reusing the arena, and preserve recognized text if UI lookup memory fails. [Local dictionaries](https://github.com/bee-san/vita-jp-overlay/blob/main/docs/local-dictionaries.md)

- **Keep private dictionaries and data private.** Ship the pinned JMdict conversion with EDRDG attribution, source/conversion hashes and CC BY-SA 4.0 licensing. User-supplied commercial dictionaries, screenshots, crops, fonts and checkpoints stay outside Git/public releases unless their redistribution rights are established. Plaintext conversion does not remove copyright. Meiki code, converted model weights and embedded dependencies have distinct license obligations; include GPL/LGPL/Apache/BSD/MIT notices and provide the scoped exact runtime source without private evaluation data. [Meiki model/source notices](https://github.com/bee-san/vita-jp-overlay/blob/main/docs/meiki-trial.md)

- **Use the native agent for hardware tests.** [vita-agent-use](https://github.com/shoui520/vita-agent-use) is a useful deployment and testing tool: verify pairing/session, inventory, logs, uploads with complete readbacks, native input results, foreground state and crash events. Keep one operator/server/client against the paired state. Preserve request/transfer IDs and ledgers when a timeout could hide an effect; recover the same operation. `accepted` is not completed. Never inject pairing/ACL/Content Manager approval, reset trust to fix a routine error, bypass policy with raw HTTP/FTP, or weaken PS+SELECT monitoring. A temporary masked SELECT sample is not evidence the user pressed the physical stop chord. [Operating guide](https://github.com/shoui520/vita-agent-use/blob/main/AGENTS.md)

- **Decode errors and analyze real dumps.** [psp2_err](https://github.com/shoui520/psp2_err) and [psp2-core-parse](https://github.com/shoui520/psp2_core_parse) are useful companions to native testing. Look up unfamiliar hex/signed/display codes before guessing. Wait for `coredump.complete`, then inspect the crashing thread, registers, modules, budgets, TTY and backtrace. Supply a matching decrypted ELF under the dump's actual runtime module name. Matching SceShell/SceLibKernel images help only when the trace enters those modules; unrelated binaries do not improve a diagnosis. Preserve full error JSON, addresses, image hashes and the distinction between agent policy errors and Sony errors.

```sh
./psp2_err --json 0x80010013
./psp2-core-parse modules dump.psp2dmp
./psp2-core-parse analyze dump.psp2dmp --image actual_module_name=matching.elf --json
```

- **Treat capture and process namespaces as resources.** A model on `ux0:` can be visible to Shell but unavailable in a retail game's namespace. The pinned model broker uses 8 KiB chunks with job/PID/foreground ownership, SHA checks and cancellation/close handling. Meiki's isolated ABI3 engine still needs the fixed game-visible `app0:` mount. A successful file readback or blank capture proves neither recognition nor a correct retail mount. On this setup, agent capture retained a 2,187,264-byte PAF pool after capture ended; prefer fresh runtime logs and input diagnostics until capture ownership/release is proved, rather than consuming Shell memory through repeated screenshot checks.

- **Match crops to the recognizer.** Meiki's current trial accepts one horizontal line, including ruby when needed, and rejects regions taller than 96 pixels before model I/O/allocation. A short rectangle alone does not prove it contains one line. Keep a hand-checked real-screenshot set separate from training/calibration; report CER, exact-line accuracy, captured geometry and backend revision. Broad dialogue boxes, stale text, dark/coloured text and mount/model failures need distinct diagnostics. Host crop CER remains a host measurement; prove changing live dialogue and post-inference cleanup separately.

- **Test the actual UI paths and packaging.** Square must reach the region editor and Circle must close the overlay even with no OCR text or an error. L+R ownership must cover opening, holding, closing and release so the game does not advance dialogue. Validate the real input handler in normal/error/local-character states, then confirm physical behavior. For Settings VPKs, validate every LiveArea PNG's CRC, dimensions, 8-bit indexed palette, opacity and non-interlaced encoding; a promoter error alone does not identify the faulty asset. A successful replacement VPK install is stronger evidence than a host ZIP build. Settings changes must preserve unrelated config keys and handle short reads/writes, failed sync/rename, backup recovery and honest save errors; the new preferences tests exercise those paths. [Settings asset checker](https://github.com/bee-san/vita-jp-overlay/blob/main/tools/check_settings_assets.py)

- **Verify the exact release and retain rollback.** Changes go through focused PRs in the bee-san fork; upstream remains pull-only. Publish after exact-head CI/review and verify downloaded release assets against SHA256SUMS. Rebuilding an existing package must remove the old manifest rather than append a duplicate. The meiki.2 packaging check found 52 ZIP members: 51 manifested payloads plus one manifest; only Shell payload bytes changed and 50 payload files stayed identical. Keep API13 kernel/worker and ABI3 engine matched, preserve public source/model pins, and exclude private config/keys/ROI/logs/screenshots. Default VOCR/local JMdict, Japanese-only character selection and no Anki queue remain the behavior. Both recognizers stay on storage; only the chosen one allocates inference memory. Back up plugins/config/ROI before a trial; do not restore an old whole database over newer user changes.

- **Use native registration and observed UI for Shell content.** Theme file copies do not register themes; Custom Themes Manager's supported UI and a fresh native theme inventory provide proof. A folder-list START batch can register unrelated pending folders, whereas per-theme details permit a scoped install. LiveArea's current agent inventory is read-only and lacks the displayed page/edit-mode state. `iconlayout.ini` is an adjunct to native AppDB, not a proven generic apply/import command. Do not edit `app.db` by hand or claim an unseen drag succeeded; verify native page/icon rows after an observed UI move. [Sony home-screen editing](https://manuals.playstation.net/document/gb/psvita/basic/custom.html), [VitaSDK layout API](https://docs.vitasdk.org/group__SceLsdbUser.html)
