# Vita overlay project lessons

These notes distinguish source/build checks, completed transfers, native state readback and physical in-game results. VOCR completed actual CLANNAD OCR jobs on the physical Vita; the user confirmed the repaired region workflow works. Hardware CER and broad compatibility remain unmeasured. The Meiki single-line trial also ran on CLANNAD (two jobs took 7,904/8,043 ms) but was removed after v0.7.12 because its MNN engine had to be copied into each game's `app0:` through rePatch; see [its v0.7.12 observations](https://github.com/bee-san/vita-jp-overlay/blob/aff03cbb559a7eccdcfbd27b9c873ea7543f1deb/docs/meiki-trial.md#physical-clannad-observations-october-11).

- **Memory is partitioned per process; SceShell has none to spare.** The game, SceShell and the kernel drivers each draw from a fixed physical budget (256 MiB, 50 MiB and 36 MiB). `*main` and `*ALL` plugins hold permanent pages in SceShell's partition, which was measured at 28-98 KiB free beside a running game; a 64 KiB static buffer (#42) and a 36 KiB module growth (#59) each broke the boot. Heavy work belongs in the game's process under `*TITLEID`. The pools, budgets, rules and the before-you-allocate checklist are in [docs/vita-memory.md](vita-memory.md); the binding rules are in [AGENTS.md](../AGENTS.md).
- **Run inference in the game process.** Keep the overlay UI under `*main`; the OCR worker is registered per game (`*TITLEID`, the installer's `--title`, never `*ALL`), filters known system apps, Settings and VitaShell and activates only for an enabled foreground game. Shell's spare PAF memory is not the game's USER memory. Report free USER bytes, requested/page-rounded allocations, allocator peaks and cleanup separately. Unused bytes inside a game-owned memblock remain owned by that game; subtracting displayed usage from a 256/333 MiB budget does not prove an allocation will fit. Raising a game allocation mode is not part of the current release. [Architecture and memory bounds](https://github.com/bee-san/vita-jp-overlay/blob/main/docs/vita-vn-ocr.md)

- **Keep dictionary work bounded.** Plain definitions and a disk-backed VJDICT2 index avoid loading a whole dictionary or index. Local lookup returns at most one entry at the selected Unicode character, reuses saved OCR text and does not tokenize the entire sentence or rerun capture. The current local result arena is 64 KiB, with bounded page-cache/deinflection scratch; those bounds are not total Shell residency. Retire the previous result before allocating/reusing the arena, and preserve recognized text if UI lookup memory fails. [Local dictionaries](https://github.com/bee-san/vita-jp-overlay/blob/main/docs/local-dictionaries.md)

- **Separate lookup position from its highlight.** PR #38 keeps character navigation and one-result lookup while defaulting to the matched source-word span, including inflection; pending or unsuccessful lookup falls back to the selected character. A tap targets the owned recognized header, with UTF-8 source offsets, CR omission, UTF-16 pairs, generation ownership and clipping handled explicitly. PAF character info provides x/line, not a glyph rectangle; the current uniform-size line pitch and trailing cell bound are layout-derived, not measured bitmap bounds. Three ASan/UBSan helper scenarios and 22 host suites passed, but native tap accuracy and routing still need hardware proof. [Touch behavior and current installation](touch-lookup.md)

- **Keep private dictionaries and data private.** Ship the pinned JMdict conversion with EDRDG attribution, source/conversion hashes and CC BY-SA 4.0 licensing. User-supplied commercial dictionaries, screenshots, crops, fonts and checkpoints stay outside Git/public releases unless their redistribution rights are established. Plaintext conversion does not remove copyright. Code, converted model weights and embedded dependencies can have distinct license obligations; ship every applicable GPL/LGPL/Apache/BSD/MIT notice and provide the scoped exact runtime source without private evaluation data. [Third-party notices](https://github.com/bee-san/vita-jp-overlay/blob/main/third_party/README.md)

- **Make optional native tools fail locally.** The first private icon sorter failed module binding with `0x8002D003` (`SCE_KERNEL_ERROR_MODULEMGR_NO_LIB`, decoded by `psp2_err`). Matching firmware NIDs and a successful link did not prove plugin binding. Resolving the four exact shared SceLsdb exports only for guarded commands restored the prior complete import set; native readback, reboot and fresh capabilities then proved activation. Keep the physical ACL, stop/controller/foreground guards and SHA-bound journal before any move. Agent `-2` means `VAU_BUSY` and `-4` means `VAU_DENIED`; map these through the agent header rather than Sony error tables. Do not mistake cached metadata details for the current error's cause. A stale PC socket can outlive `serve`: check the process and restart normally with saved state rather than resetting trust. [Current recovery and sorting boundary](todo-20261011.md)

- **Use the native agent for hardware tests.** [vita-agent-use](https://github.com/shoui520/vita-agent-use) is a useful deployment and testing tool: verify pairing/session, inventory, logs, uploads with complete readbacks, native input results, foreground state and crash events. Keep one operator/server/client against the paired state. Preserve request/transfer IDs and ledgers when a timeout could hide an effect; recover the same operation. `accepted` is not completed. Never inject pairing/ACL/Content Manager approval, reset trust to fix a routine error, bypass policy with raw HTTP/FTP, or weaken PS+SELECT monitoring. A temporary masked SELECT sample is not evidence the user pressed the physical stop chord. [Operating guide](https://github.com/shoui520/vita-agent-use/blob/main/AGENTS.md)

- **Handle long verification and diagnostic limits explicitly.** The native agent can spend longer than its ordinary 20-second host response budget hashing a large disk-backed dictionary, and commit/recovery can hash it more than once. A tested isolated host client gives only large-file hash steps a bounded 600-second response budget and emits truthful waiting events every five seconds; chunk and ordinary RPC limits, native stop checks, pinning, ACLs and operation identities remain unchanged. Waiting events prove host waiting, not native hashing progress or publication. The private Daijirin staging and full SHA-256 verification completed in 53.273 seconds, but commit returned `-9` and recovery reached the 600-second response deadline while the device went dark. After the user woke it and the session reconnected, the saved SHA-bound native operation completed with code 0 in 72.029 native seconds, 72.143 seconds elapsed; a final installed-path stat matched its byte count. That establishes publication through native hash/recovery and stat, rather than a full dictionary download. Preserve the operation rather than restarting the upload, and do not infer the earlier error's cause from those observations. Keep that adaptation private until it is reviewed for the tool itself. UDP diagnostics deliberately drop queries less than one second apart; separate status/input requests by more than a second. A `stop_buttons_masked` observation with SELECT absent is a guard fault, not proof of a physical stop. Restore a UI state where the chord is observable; do not alter button masks or ignore the guard.

- **Decode errors and analyze real dumps.** [psp2_err](https://github.com/shoui520/psp2_err) and [psp2-core-parse](https://github.com/shoui520/psp2_core_parse) are useful companions to native testing. Look up unfamiliar hex/signed/display codes before guessing. Wait for `coredump.complete`, then inspect the crashing thread, registers, modules, budgets, TTY and backtrace. Supply a matching decrypted ELF under the dump's actual runtime module name. Matching SceShell/SceLibKernel images help only when the trace enters those modules; unrelated binaries do not improve a diagnosis. Preserve full error JSON, addresses, image hashes and the distinction between agent policy errors and Sony errors.

```sh
./psp2_err --json 0x80010013
./psp2-core-parse modules dump.psp2dmp
./psp2-core-parse analyze dump.psp2dmp --image actual_module_name=matching.elf --json
```

- **Treat capture and process namespaces as resources.** A model on `ux0:` can be visible to Shell but unavailable in a retail game's namespace. The pinned model broker uses 32 KiB chunks with job/PID/foreground ownership, SHA checks and cancellation/close handling; the game keeps the verified weights resident and re-reads them only when the file's size or modification time changes. Executable code is different: a module the game loads itself must be on a path the game can see, which is why the removed Meiki engine needed a per-title `app0:` mount. A successful file readback or blank capture proves neither recognition nor a correct retail mount. On this setup, agent capture retained a 2,187,264-byte PAF pool after capture ended; prefer fresh runtime logs and input diagnostics until capture ownership/release is proved, rather than consuming Shell memory through repeated screenshot checks.

- **Match crops to the recognizer.** A single-line recognizer such as the removed Meiki trial needs one horizontal line; a short rectangle alone does not prove it contains one line. Keep a hand-checked real-screenshot set separate from training/calibration; report CER, exact-line accuracy, captured geometry and backend revision. Broad dialogue boxes, stale text, dark/coloured text and mount/model failures need distinct diagnostics. Host crop CER remains a host measurement; prove changing live dialogue and post-inference cleanup separately.

- **Test the actual UI paths and packaging.** Square must reach the region editor and Circle must close the overlay even with no OCR text or an error. L+R ownership must cover opening, holding, closing and release so the game does not advance dialogue. Validate the real input handler in normal/error/local-character states, then confirm physical behavior. For Settings VPKs, validate every LiveArea PNG's CRC, dimensions, 8-bit indexed palette, opacity and non-interlaced encoding; a promoter error alone does not identify the faulty asset. A successful replacement VPK install is stronger evidence than a host ZIP build. Settings changes must preserve unrelated config keys and handle short reads/writes, failed sync/rename, backup recovery and honest save errors; the new preferences tests exercise those paths. [Settings asset checker](https://github.com/bee-san/vita-jp-overlay/blob/main/tools/check_settings_assets.py)

- **Design Settings for the Vita screen.** [PR #34](https://github.com/bee-san/vita-jp-overlay/pull/34), exact head `c9ec54f9a6562ad61cbb8d9e4876e86028e652f4`, replaces five small rows with three 80-pixel cards, separates two-line titles from IDs, enlarges page/engine touch targets and keeps readable save-error status. Hold only three icon textures and retain their unload-on-scroll ownership. Use public PVF advances to wrap and center text; calibrate em targets with full-width glyph advances rather than treating PVF's nominal `text_height` as a bitmap-height measurement. The supported API scales its existing raster, so a synthetic preview cannot prove native glyph bounds, sharpness or physical readability. The actual complete input loop passed 12 host scenarios under ASan/UBSan, and native Release packaging passed. The installed v0.7.7 app nevertheless crashed during PNG icon loading. After the v0.7.8 runtime repair, native foreground survival and controller/config-readback checks passed; firmware font bounds and physical readability remain pending. A static SFO `APP_VER` of `01.00` does not identify the release: use exact executable bytes and package provenance. [Current measurement method and limits](settings-readability.md)

- **Audit dependency ABI in the actual executable.** A matching native Settings dump traced `C2-12828-1` to PNG cleanup. The SDK libpng had a 92-byte jump buffer while the linked ARM `setjmp`/`longjmp` transferred 104 bytes, corrupting adjacent metadata. [PR #36](https://github.com/bee-san/vita-jp-overlay/pull/36), merged as `b0642493688c0f31bc33738d937d876ba0edbab6` after exact-head host/Vita CI, builds pinned unmodified libpng 1.6.58 with current project headers: its 160-byte buffer fits the measured save/restore. Keep the private library local to the project and retain the libvita2d pin and icons. Fail the native link if the actual instructions exceed buffer/metadata bounds or use an unrecognized layout. Host UI stubs and valid artwork cannot establish this native ABI. [Diagnosis, API contract and binary gate](settings-png-runtime.md)

- **Check saved state after each native input.** The repaired Settings app stayed in the foreground over a measured 100.106 seconds, with no crashes in the sampled native event window and zero reported lost events. An initial Select action completed but its config readback unexpectedly showed Japanese-only off; catch that before assuming unchanged state or sending dependent actions. Two front-touch actions normalized focus, then five controller actions and full config readbacks checked Meiki/VOCR, the already-off Japanese-only setting and restoration to on. A later, separate native touch/controller check measured Japanese-only on-to-off-to-on with a full config download after every action. The final config exactly restored VOCR/Japanese-only-on and unrelated keys. An uncertain promoter response after a disconnect was reconciled through installed registry/readback and actual app controls, not re-labelled a terminal installation receipt. Native saved choices do not prove physical typography, in-game Japanese navigation, dictionary lookup or OCR CER. [Installation and remaining checks](todo-20261011.md)

- **Verify the exact release and retain rollback.** Changes go through focused PRs in the bee-san fork; upstream remains pull-only. Publish after exact-head CI/review and verify downloaded release assets against SHA256SUMS. Rebuilding an existing package must remove the old manifest rather than append a duplicate. The meiki.2 packaging check found 52 ZIP members: 51 manifested payloads plus one manifest; only Shell payload bytes changed and 50 payload files stayed identical. Keep the API13 kernel, Shell and worker matched, preserve public source/model pins, and exclude private config/keys/ROI/logs/screenshots. Default VOCR/local JMdict, Japanese-only character selection and Anki mining off (`anki_mining = off`: no queue directory, thread or memory) remain the behavior. Installed recognizer models stay on storage; only the chosen one allocates inference memory. Back up plugins/config/ROI before a trial; do not restore an old whole database over newer user changes.

- **Use native registration and observed UI for Shell content.** Theme file copies do not register themes; Custom Themes Manager's supported UI and a fresh native theme inventory provide proof. A folder-list START batch can register unrelated pending folders, whereas per-theme details permit a scoped install. LiveArea's current agent inventory is read-only and lacks the displayed page/edit-mode state. `iconlayout.ini` is an adjunct to native AppDB, not a proven generic apply/import command. Do not edit `app.db` by hand or claim an unseen drag succeeded; verify native page/icon rows after an observed UI move. [Sony home-screen editing](https://manuals.playstation.net/document/gb/psvita/basic/custom.html), [VitaSDK layout API](https://docs.vitasdk.org/group__SceLsdbUser.html)

- **A built native sorter is still a candidate.** Local agent source `d5b9221` uses the native icon-move API with a SHA-bound complete plan, read-only layout checks, retained operation journal and stop/ACL checks immediately before the effect. Protocol tests and 12 ASan/UBSan coordinator cases passed. Its first runtime had full native readback and an accepted reboot request but failed library binding. The revised helper later booted and physical approval was recorded; its guarded call returned `SCE_ERROR_ERRNO_EINVAL`, and a complete read still matched all original coordinates. The user canceled sorting, so no successful move or persistence result is claimed. The build audit caught stale callback offsets after a fast build bypassed header-dependency refresh; removing all 110 objects and rebuilding restored the unchanged objects before deployment. A successful link alone did not prove the correct object layout. Preserve the 59-app/seven-page plan and unrelated registration state; do not claim sorting complete from host tests or publish the user's title inventory. [Trial and cancellation](todo-20261011.md)

- **Reconcile an uncertain promotion without rewriting its history.** The v0.7.9 bundle passes all 60 payload hashes and archive CRC checks; all six independently downloaded release assets match their audited candidates. Only Shell changes among `ur0/tai` plugins, to 150,500 bytes; the installed Shell and 277,608-byte Settings executable match the release completely. A connection loss left promoter status uncertain, while later native registration/foreground launch established an executable app. Four actual Settings touch/controller actions then saved Character → Whole word → Character → Whole word, with full config readbacks preserving VOCR, Japanese-only ON and unrelated bytes. Installed bytes, registration, actual controls and GitHub publication each have their own evidence; none reclassifies the retained promoter status or proves in-game touches. [Exact source, artifacts and remaining checks](todo-20261011.md#v079-touchhighlight-installation-checkpoint)

- **Separate native work from host waiting.** A full staged-file dictionary hash passed in 53.273 seconds; a later commit returned recovery-required, and recovery reached its 600-second response bound while the device went dark. Waiting notifications only establish a host wait. A matching installed-agent binary audit found both power-tick calls pass `1`, cancelling automatic suspension only, rather than the SDK default `0` for all idle timers. The inspected call sites also sit outside synchronous pairing/command work, so blocking requests can postpone ticks. These establish two keep-awake weaknesses. New uptime after a reconnect makes standby-versus-restart uncertain, and neither weakness proves every disconnect's cause. The saved operation later recovered to terminal completion and its installed file was checked. Preserve the transfer and pending command identities, then use supported reconnect/recovery. Do not replace the file, weaken the stop guard or claim publication from a successful staging hash. Likewise, a verified Shell file replacement does not prove it has loaded: confirm a fresh boot separately, and separate Settings promotion/readback from actual launch and physical UI checks. [VitaSDK power-tick contract](https://docs.vitasdk.org/group__SceProcessmgrKernel.html)

- **Keep active control awake independently of blocking requests.** Clean local agent revision `1d8a438d51454c27508a42849e0674080f01e9cd` adds an independent worker with an 8 KiB stack request, five-second default ticks and cooperative join/deletion ownership. Its actual-worker harness passed 18 ASan/UBSan cases and 20 lifecycles; native import ABI is unchanged. Only the runtime was replaced, with full readback before reboot. Fresh native logs then report worker init 0 and first DEFAULT tick 0/count 1; Settings relaunched with no reported system UI overlay and the intended config byte-identical. A later 374.066-second interval without native/wake/input requests ended with a healthy response on the same boot and the same foreground Settings process, with no disconnect/stop/coredump events and zero lost events in the sampled window. This establishes quiet connection survival; the endpoint snapshot turns the screen on and does not prove actual OLED visibility throughout the interval. Activity is limited to an authenticated command connection or previously authorized pending native work; inactive pairing still uses the original AUTO_SUSPEND policy. Do not claim all pairing waits stay awake or a deployed upstream agent release. [Activation and remaining display checks](todo-20261011.md)
